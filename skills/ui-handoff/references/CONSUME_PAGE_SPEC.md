# Consume Page Spec

根据 `page-structure.md` 在当前项目中实现页面。

规则：

1. `page-structure.md` 是页面内容、功能和交互的真相源。
   不得删除、增加或擅自改变其中已经明确的功能和交互。

2. 当前 Codebase 是页面视觉风格和实现方式的主要参考。
   页面布局、间距、字号、颜色、组件样式、表格样式、表单样式、Dialog / Drawer 等，应优先与当前项目已有页面保持一致。

3. 产品原型的视觉只作为参考。
   如果产品原型视觉与当前项目已经形成的统一风格冲突，以当前项目风格为准，但不得因此改变产品原型定义的内容、功能和交互。
4. 优先使用 `codebase-memory-mcp` 查找相似页面和可复用组件；如果当前环境未提供该工具，则使用 Coding Agent 自带的代码搜索能力完成相同任务。找到候选实现后，只读取少量相关源码确认。

5. 有合适实现就复用；没有完整可复用页面时，组合现有组件；仍没有合适实现时再新建局部实现。

6. 当前只做 UI、Mock 数据和前端交互，不接后台 API，不实现真实业务逻辑。

## 判断原则

- 页面“有什么” → 以 `page-structure.md` 为准。
- 页面“怎么操作” → 以 `page-structure.md` 为准。
- 页面“怎么排版、什么风格” → 以当前 Codebase 为准。
- 页面“怎么实现” → 结合当前 Codebase 决定。
